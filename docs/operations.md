# OrbitDesk operations and free-use boundaries

The implementation is code-ready only after local checks. Google grants, deployment, account capacity, AI eligibility, live sends and a 48–72-hour observation run remain human checks. Development uses injected fake ports; no credential, billing, email or calendar action is part of local verification.

## Manual and scheduled imports

Automation starts disabled. The settings owner must enable it only after each selected Google account and writable destination has passed the live checklist. This module never installs a trigger. A deployed trigger must invoke the same owner-configured service with automationEnabled true; manual requests use manual true and still consume the same durable budget.

SyncScheduler accepts a narrow SyncPort.page(connectionId, checkpoint, {maxCalls, deadlineAt}). Each page must stay within its allowance, persist source/task records idempotently, and then return its checkpoint. A page must never use AI, send mail, submit coursework or reconcile calendar writes. The scheduler stores the new checkpoint only after the page returns successfully. If execution stops between persistence and checkpointing, replay upserts the same source-scoped records. Provider adapters must check deadlines between requests; synchronous network calls cannot be cancelled by this scheduler.

Default bounds are three account pages, fifteen reserved Google calls, five calls per page, twenty seconds per round, five hundred calls per UTC day, and fifteen seconds between manual runs. These are conservative app limits, not a claim that Google grants that quota or that nine accounts fit one Apps Script run. Nine unique active accounts rotate across rounds using the last attempted account saved in Sheets. Paused, disconnected and unreadable accounts do not poll. Each provider failure backs off only that account; a 429 honors bounded Retry-After. Unknown call consumption charges the entire reservation. Successful pages refund unused calls. A six hundred second durable lease, acquired through RecordStore.atomic (Script Lock in production), rejects overlapping rounds. Store access and lease acquisition must use the same backing Sheets document and script lock.

Health reports the actual last fully completed import and its age, checkpoint, error and next-attempt time. An unfinished page does not make an old account look freshly synced. Checkpoint progress and stored tasks may exist before the first fully completed import. Persistent budgets use UTC dates; account and scheduler records survive reloads. Running a page cannot bypass daily limits by using the manual button.

## Reply safety and uncertain delivery

ReplyService.send receives the server-constructed user actor, exact draft id/version, request id and the literal instruction send. The owner RPC guard must derive the actor from the authenticated session; never accept actor identity, instruction or userContent from imported messages or AI output. The user must supply nonempty content and review the final recipients/body. Saving any change increments the draft version, invalidating an earlier send request. Imported drafts remain blocked until explicit user save clears importedUnreviewed.

Within one atomic write the service saves both a pending draft and a request operation. It releases the storage lock before the Gmail call so the pending state is durable before any network side effect. A duplicate request returns the stored result. A different request cannot send a pending, unknown or sent draft. The Gmail adapter sends base64url UTF-8 MIME with the original thread id, sanitized recipients, subject, In-Reply-To and References; it rejects injected headers and uses no Bcc or attachments.

A network timeout, malformed confirmation, unclassified provider error or uncertain reply-thread result becomes unknown and is never retried automatically. A process terminated while a request is in flight may leave pending; treat that as potentially delivered. Inspect Sent in the same Google account/thread before taking a fresh user-directed action. Do not resolve pending/unknown by replaying the original request or merely changing its request id. Confirmed permission/rate-limit rejection is failed; editing and a fresh explicit instruction are still required before another attempt. A successful Gmail response means provider acceptance, not proof of recipient delivery.

## Optional Groq proposals

AI is off unless enabled, explicit data-processing consent is true, a private user-supplied API key and model are configured, and the human has confirmed that the key's organization remains on an eligible Free plan. Keep keys in restricted Script Properties, never in Sheets, exports, browser state or logs. No default key, model, alternative provider, paid tier, billing activation or fallback retry exists. A 429 leaves structured Google imports and manual controls usable.

The adapter uses the documented [Groq Chat Completions endpoint](https://console.groq.com/docs/api-reference) and [strict structured outputs](https://console.groq.com/docs/structured-outputs). Check current model support before configuring a model. The application submits one bounded source from one explicit account plus optional user wording. It supplies no tools, credentials, other accounts or action capability. Output accepts only summary, task title/notes proposals and reply wording; unknown fields and action instructions fail schema validation. Proposal or rephrase output never sends, saves, creates tasks, changes recipients or grants permission by itself. Rephrasing requires user content and imported-draft review.

Groq's API contract does not offer a request parameter that proves a key is Free-only. Human confirmation is a deployment gate, not programmatic billing verification. Review organization plan/key/model eligibility before every enabling change; disable AI if the organization is upgraded. See [Groq billing FAQs](https://console.groq.com/docs/billing-faqs) and [current rate limits](https://console.groq.com/docs/rate-limits). No live Groq processing or eligibility measurement was performed here. Local adapter tests use fabricated responses only.
